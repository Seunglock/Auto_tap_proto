프론트엔드-백엔드 연동 현황 보고
길,글 프로젝트
1. 개요
본 보고서는 프론트엔드 프로토타입과 백엔드 활동 수집기의 현재 상태를 점검하고, 두 모듈을 연결하기 위해 필요한 작업을 정리한 것입니다.
2. 현재 상태
프론트엔드는 화면과 동작이 대부분 완성된 상태입니다. 단일 HTML 파일 안에 화면 구성, 스타일, 타임라인 슬라이더 로직이 모두 포함되어 있으며 동작에는 문제가 없습니다. 다만 화면에 표시하는 활동 데이터가 코드 내부에 직접 작성되어 있어, 실제 수집 기록과는 연결되어 있지 않습니다. 현재 값은 예시로 넣어 둔 것입니다.
백엔드는 브라우저를 실행하여 사용자가 페이지를 이동할 때 화면이 어떻게 변화했는지를 기록하고, 그 결과를 날짜별 데이터베이스 파일에 저장합니다. 한 건당 주소, 시각, 그리고 페이지 진입 시점과 이탈 시점의 화면 차이를 텍스트로 담습니다. 수집 동작 자체는 정상적으로 작동합니다.
두 모듈을 연결하려고 보면, 백엔드가 저장하는 데이터의 형태와 프론트엔드가 요구하는 데이터의 형태가 상당히 다릅니다. 백엔드는 가공되지 않은 변화 기록만 저장하는 반면, 프론트엔드는 시간 구간, 분류, 제목, 요약, 태그가 모두 채워진 활동 단위를 요구합니다. 그 사이를 채우는 처리 단계가 빠져 있습니다.
3. 데이터 단위 비교

| 구분 | 프론트엔드가 다루는 단위 | 백엔드가 만드는 단위 |
| --- | --- | --- |
| **형태** | 정리된 활동(에피소드) 한 건 | 가공되지 않은 변화 기록 한 건 |
| **구성** | 시작시각, 종료시각, 분류, 제목, 지속시간, 링크, 요약, 태그 | 주소, 시각, 화면 차이 텍스트 |
| **저장 위치** | HTML 코드 내부에 직접 작성 | 날짜별 데이터베이스 파일 |

4. 항목별 호환성

| 프론트엔드 항목 | 백엔드 대응 여부 | 상태 |
| --- | --- | --- |
| **종료시각** | 저장된 시각 값으로 대응 | 변환 가능 |
| **링크** | 주소 값 한 건 존재 | 형태만 조정 필요 |
| **시작시각** | 내부적으로 보유하나 미저장 | 누락 |
| **지속시간** | 시작시각이 없어 산출 불가 | 산출 불가 |
| **분류(개발/영상/뉴스/민감)** | 분류 기준 없음 | 없음 |
| **제목** | 없음 | 없음 |
| **요약** | 변화 기록 원문만 존재 | 없음 |
| **태그** | 없음 | 없음 |
| **주간 단위 조회** | 날짜별 파일로 분리 저장 | 다중 파일 처리 필요 |

5. 미비점
종합하면 세 가지가 비어 있습니다.
첫째, 활동 시작시각이 데이터베이스에 저장되지 않습니다. 내부적으로는 시작시각을 보유하고 있으나 저장 단계에서 누락되어, 활동의 지속시간을 계산할 수 없습니다.
둘째, 분류 기준이 없습니다. 프론트엔드의 네 가지 분류에 해당하는 판단 로직이 백엔드에 존재하지 않습니다.
셋째, 두 모듈을 잇는 전달 경로가 없습니다. 백엔드는 데이터베이스에 저장만 하고, 프론트엔드는 외부 데이터를 불러오는 코드를 가지고 있지 않습니다.
6. 개선 방안
작업은 다음 순서로 진행하는 것이 적절합니다.
먼저 백엔드에서 시작시각을 함께 저장하도록 항목을 하나 추가합니다. 소규모 수정이며, 이 작업만으로 시작시각과 종료시각이 모두 확보되어 지속시간이 자동으로 산출됩니다.
다음으로 저장된 기록을 사람이 보는 활동 단위로 묶는 가공 단계를 추가합니다. 같은 페이지에서 연속으로 발생한 변화들을 하나로 합쳐 활동 한 건으로 만듭니다.
분류는 주소 규칙을 기준으로 처리합니다. 개발 관련 사이트, 영상 사이트, 뉴스 및 자료 사이트를 각각 규칙으로 지정하고, 사전에 정한 민감 주소 목록에 해당하면 민감 분류로 분리합니다. 규칙 기반 방식은 분류 근거가 코드에 그대로 드러나고, 같은 입력에 대해 항상 같은 결과를 내므로 검증이 용이합니다.
제목과 요약은 정해진 서식에 수집된 값을 채워 생성합니다. 주소, 방문 시각, 머문 시간, 페이지 제목 등을 일정한 틀에 맞추면 충분히 읽을 수 있는 문장이 만들어집니다. 태그 또한 주소와 경로에서 추출합니다. 이 방식은 가공 과정 전체가 규칙으로 설명되며 출력이 일정합니다.
마지막으로 가공 결과를 날짜별 파일로 내보내고, 프론트엔드가 해당 파일을 불러오도록 변경합니다. 프론트엔드의 슬라이더와 카드 표시 로직은 수정할 필요가 거의 없으며, 데이터를 받는 입구만 교체하면 됩니다.
7. 결론
프론트엔드는 완성에 가깝고 백엔드는 수집 단계까지 동작하는 상태이며, 비어 있는 부분은 그 사이의 가공과 전달입니다. 가공 과정을 규칙 기반으로 구성하면 동작이 투명하고 결과가 일정하여, 데이터가 어떤 과정을 거쳐 만들어졌는지 코드만으로 설명할 수 있습니다.
